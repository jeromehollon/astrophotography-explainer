- Flats: each flat has the dark flat subtracted, or the bias if there's no dark flat, or nothing. The flats are then averaged with multiplicative normalization.
  - WBPP's automatic rejection would pick linear-fit clipping for 25 flats. I recommend winsorized clipping in our precompute; the difference is negligible for panel flats.

18	## 0. WBPP pipeline order (WBPP 3.0.1)
19	
20	WBPP runs these steps in order. Items marked *(off)* are disabled by default or don't apply to mono data.
21	
22	1. Build master bias, master dark, master dark-flat and master flat.
23	2. Calibrate lights (ImageCalibration). Automatic cosmetic correction runs inside this step.
24	3. Linear defect correction *(off)*, then CosmeticCorrection process *(off)*, then Debayer *(mono: n/a)*.
25	4. Measurements: PSF signal and noise estimates, FWHM, eccentricity. Then weights.
26	5. Frame selection *(off)*, then pick the registration reference frame.
27	6. Plate solve the reference, then register with StarAlignment (drizzle data generated).
28	7. Build the LN reference (an integration of the best frames), then run LocalNormalization. This produces `.xnml` files.
29	8. ImageIntegration, then drizzle *(if enabled)*, then autocrop.
30	
31	Source: Landmann §10, and the `doCalibrate`/integration code in `BPP-processing.js`.

35	## 1. Master calibration frames
36	
37	### 1.1 Bias and dark masters
38	
39	WBPP integrates the raw frames with **no pre-calibration**. The master dark is *not* bias-subtracted, so it contains the bias pedestal. WBPP 2.5.0 removed compatibility with pre-calibrated master darks: the code comment reads `IC.calibrateDark = engine.overscan.enabled || masterBiasEnabled; // compatibility with pre-calibrated master dark has been removed`.
40	
41	The ImageIntegration settings for bias and dark (`BPP-processing.js`, `default:` branch) are:
42	- `combination = Average`
43	- `normalization = NoNormalization`
44	- `rejectionNormalization = NoRejectionNormalization`
45	- `weightMode = DontCare` (all weights = 1)
46	- `rangeClipLow/High = false`
47	- Rejection: auto (§4.7). **Bias and darks always use Winsorized σ-clipping** when there are 6 or more frames, whatever the count. Parameters are σ low 4, σ high 3, and Winsorization cutoff 5.
48	
49	### 1.2 Flats and dark-flats
50	
51	A master dark-flat is just a master dark built at the flat's exposure (the Dark image type), so it gets the §1.1 settings.
52	
53	`BPP-CalibrationMatcher.getCalibrationGroupsFor()` decides how each flat frame is calibrated:
54	- WBPP looks up a master bias `mb` and a master dark `md` matching the flat's exposure. When `mb` exists, an exact exposure match is required.
55	- **The bias is dropped whenever a master dark (here, the dark-flat) is present and not optimized** (`optimizeDarks` defaults to `false`).
56	
57	So each flat is calibrated as:
58	```
59	F_cal = F − MDF      if a matching dark-flat exists
60	F_cal = F − MB       else if a master bias exists
61	F_cal = F            else (uncalibrated flats → vignetting UNDER-corrected later)
62	```
63	`IC.calibrateFlat = false` because each flat frame was already calibrated before integration.
64	
65	The master-flat integration settings (`case ImageType.Flat`) are:
66	- `combination = Average`
67	- `normalization = Multiplicative` (output)
68	- `rejectionNormalization = EqualizeFluxes`
69	- `weightMode = DontCare`
70	- no range rejection
71	- large-scale rejection off
72	- Rejection: auto. With 25 flats that gives **Linear Fit clipping** (low 5, high 3.5), because n > 15 and the frames are not the bias or dark type.
73	
74	The normalization formulas *(reconstructed; the doc gives these in prose)*, where `m` is the median of each whole frame and `0` is the reference (first) frame:
75	- Multiplicative output: `y_i = x_i · m_0 / m_i`
76	- Equalize fluxes (rejection): the same multiplicative form, used only when deciding which pixels to reject.
77	
78	### 1.3 Dark optimization (off by default; described for completeness)
79	
80	`BPP.Defaults.optimizeDarks = false`. When it's enabled, ImageCalibration computes a factor `k` per frame by minimizing noise (a k-σ noise estimate) of the calibrated frame:
81	```
82	Cal = ((L − MB) − k·(MD − MB)) / MF · f
83	```
84	It is only relevant for cameras without cooling or with mismatched exposures. Amp glow often fails to calibrate out with it. Sources: IC doc §1.6 and Landmann §7.2.

95	|---|---|---|

118	## 3. Measurement, weighting, registration
119	
120	### 3.1 Subframe weights
121	
122	- Weighting is on by default. The WBPP default method is **PSF Signal Weight (PSFSW)**. The alternatives are PSF SNR, PSF Scale SNR, SNR estimate, or a custom formula written to a CSV file.
123	- WBPP writes weights to the `WBPPWGHT` keyword. ImageIntegration then uses `weightScale = BWMV` and `minWeight = 0.05`.
124	- **PSFSW** combines total PSF flux (`TFlux`) and mean PSF flux (`TMeanFlux`), from hybrid PSF/aperture photometry of detected stars, with noise `N*` and background `M*`, normalized by constants α and β. **PSF SNR** is a ratio-of-powers form built from the same flux terms and `N*²`.
125	- The exact equations are SVG images (ImageWeighting doc eq. 16 and 18), so they are **UNVERIFIED** here.
126	- Combination: `weighted average = Σ w_i·y_i / Σ w_i` over non-rejected pixels. Weights are relative to the reference image, which has weight 1 by convention (II doc).
127	
128	### 3.2 Registration (StarAlignment)
129	
130	WBPP defaults: `saPixelInterpolation = Auto`, `saClampingThreshold = 0.3`, `saDistortionCorrection = false` (a projective, 8-parameter homography), plate solving on, and drizzle data generated.
131	- **Auto interpolation** selects Lanczos-3 for same-scale registration (https://pixinsight.com/doc/docs/InterpolationAlgorithms/InterpolationAlgorithms.html). Cubic filters (Mitchell–Netravali) are for strong downsampling only.
132	- **Lanczos-3 with clamping** (`LanczosInterpolation.h`) works as follows:
133	  - Kernel: `L(t) = sinc(t)·sinc(t/3)` for |t| < 3.
134	  - It uses a 6×6 neighbourhood. For a sample position `(x,y)`, `x0 = floor(x)`, `dx = x − x0` (same for y), and taps run over `x0−2 … x0+3`.
135	  - Each tap contributes `s = v·w`, with separable weight `w = L(j − dx)·L(i − dy)`. Positive `s` accumulates into `sp, wp`; negative `s` into `sn += −s, wn += −w`.
136	  - Clamping: `r = sn/sp`. If `r ≥ 1`, return `sp/wp`. If `r > 0.3`, then `c = 1 − ((r − 0.3)/0.7)²` and `sn *= c, wn *= c`.
137	  - Result: `(sp − sn)/(wp − wn)`.
138	  - Border taps mirror the image (`f[−x]`, `f[2W−2−x]`).
139	- StarAlignment sets output pixels that map outside the source to **0**. Integration later discards them through range rejection (§4.8).
140	
141	### 3.3 `.xdrz` alignment data: coordinate convention (verified)
142	
143	- `AlignmentMatrix` holds 9 numbers, row-major, forming the homography `H`. For an output pixel `(u,v)`: `[x',y',w]ᵀ = H·[u,v,1]ᵀ`, then `x = x'/w`, `y = y'/w`.
144	- **`H` maps reference-frame coordinates to raw-frame coordinates.** That's the inverse-warp direction: for each output pixel, it gives the position to sample in the raw frame.
145	  - Reference frame: `FRAME_0007` (its matrix is the identity).
146	  - Empirical check: frame 3 has `dx = −26.3`, and a star at raw x = 3056 appears at registered x = 3084.
147	- `AlignmentOrigin = {0.5,0.5}`. From `DrizzleData.h`: *"corresponds to image coordinates {0,0} in the coordinate system used for image registration… the center of the top-left pixel."* So in registration coordinates, pixel `(i,j)` has its centre at `(i,j)`. That matches PCL interpolation's `x0 = floor(x)` convention, so `x` and `y` feed the Lanczos sampler directly, with no ±0.5 shift. Row 0 is the top row (XISF order).
148	- To use another reference `r`, sample raw frame `i` at `H_i · H_r⁻¹ · p`, where `p` is a pixel in r's raw grid.
149	- **2×2 binned grids:** binned index `b` has its centre at native `2b + 0.5`. With `S = [[2,0,0.5],[0,2,0.5],[0,0,1]]`, use `H_bin(i←r) = S⁻¹ · H_i · H_r⁻¹ · S`.

153	## 4. Integration (ImageIntegration) — what WBPP sets for lights
154	
155	### 4.1 Light settings (WBPP 3.0.1 code, `case ImageType.Light`)
156	
157	- `combination = Average`
158	- `weightMode = PSFSignalWeight` (default)
159	- `weightScale = BWMV`
160	- `minWeight = 0.05`
161	- Without LN: `normalization = AdditiveWithScaling` and `rejectionNormalization = Scale` ("scaling + zero offset").
162	- With LN (**WBPP's default**, `localnormalization: true`): both normalizations switch to `LocalNormalization` and `LocalRejectionNormalization`, and `subtractPedestals = false`.
163	- `clipLow = clipHigh = true`
164	- `rangeClipLow = true`, `rangeLow = 0`, `rangeClipHigh = false`

166	- `largeScaleClipLow/High = false`
167	- `winsorizationCutoff = 5`
168	- Auto rejection (§4.7).
169	
170	### 4.2 Location and scale estimators
171	
172	- **Location:** `m` = median of the whole image. The exception is the IKSS scale estimator, which uses the IKSS location instead.
173	- **Scale (WBPP: BWMV):** `s` = √(biweight midvariance), computed around the median `M`:
174	  ```
175	  y_k = (x_k − M) / (9·MAD);   a_k = 1 if |y_k| < 1 else 0
176	  BWMV = n · Σ a_k (x_k − M)² (1 − y_k²)⁴  /  ( Σ a_k (1 − y_k²)(1 − 5y_k²) )²
177	  s = sqrt(BWMV)
178	  ```
179	  This is Wilcox §3.12, as quoted in the II doc. MAD is the raw median absolute deviation.
180	
181	### 4.3 Global normalization formulas *(reconstructed)*
182	
183	Here `0` is the reference image. In ImageIntegration that's the first input image by convention (II doc).
184	- **Scaling factor:** `k_i = s_0 / s_i`
185	- **Scale + zero offset** (rejection normalization): `y_i = (x_i − m_i)·k_i + m_0`
186	- **Additive:** `y_i = x_i − m_i + m_0`
187	- **Multiplicative:** `y_i = x_i · m_0/m_i`
188	- **Additive with scaling** (output): `y_i = (x_i − m_i)·k_i + m_0`, the same as scale + zero offset.
189	- **Multiplicative with scaling:** `y_i = x_i · k_i · m_0/m_i`
190	
191	So for lights without LN, **one normalized stack serves both rejection and combination**.
192	
193	### 4.4 Local normalization (WBPP default; we do not replicate it)
194	
195	- Per-pixel form: `y = k(x,y)·(x − b_i(x,y)) + b_0(x,y)`. The `b` terms are local background models and `k` is a local scale.
196	- WBPP settings:
197	  - Method: PSF flux photometry (`localnormalizationMethod = PSFFlux`).
198	  - `scale = min(W,H)/gridSize`, with gridSize 4. That's about 1042 px here; LN supports discrete scales from 32 to 8192 (UNVERIFIED how it rounds).
199	  - LN reference: an integration of the best frames (up to 20) by PSFSW. Low and high clipping levels are 4.5e-5 and 0.85.
200	  - Reference rejection 3.0, target rejection 3.2.
201	- LN tracks time-varying gradients and partly normalizes clouds. Sources: `BPP-processing.js` around line 540, LN doc §1–3.
202	
203	### 4.5 Combination
204	
205	- **Average:** `Σ w·y / Σ w` over the surviving pixels.
206	- **Median:** the median of the surviving pixels. It gives about 20% lower SNR than the average for the same frames (II doc: the standard error of the median is √(π/2)≈1.25× that of the mean). Its value is implicit robustness to outliers.
207	
208	### 4.6 Rejection algorithms (per pixel stack, on normalized values)
209	
210	The PixInsight defaults are the ones WBPP sets (`BPP-StackEngine.js`). Every iterative method stops when nothing more is rejected or fewer than 3 pixels remain.
211

218	  2. Reject `x` when `(m − x)/σ > σ_low` or `(x − m)/σ > σ_high`.
